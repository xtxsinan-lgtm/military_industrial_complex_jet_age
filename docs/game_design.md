## 1. 核心概念

玩家经营一家**战斗机制造商**：

- 研发科技树
- 亲手绘制翼型，设计机体
- 做风洞实验
- 用游戏内置的模拟器估算飞机性能
- 和本国**史实存在的飞机项目**竞标，赢得订单
- 向外国出口，间接影响地缘政治和战争结果

**设计原则**：设计是主角，战争是检验场。空气动力学要变成**有取舍、有风险的决策**，而不是让人填参数的计算器。

**主题**：航空军工复合体。艾森豪威尔 1961 年告别演说中警告的"军工复合体"，以及国会、军方、军工企业之间的"铁三角"关系。

**基调**：**中性模拟**。如实呈现军工产业的运作方式，不做政治讽刺，也不做道德评判。

**时间跨度**：**1945–2030**，从第一代喷气战斗机一直到第六代战机概念和无人僚机。

## 2. 参考作品与市场定位

### 2.1 参考作品

| 作品 | 借鉴点 |
|---|---|
| **Automation: The Car Company Tycoon Game** | 设计 + 经营的核心循环。游戏本身不能驾驶，车辆导出到 BeamNG.drive 才能开 |
| **Rule the Waves 1/2/3** | 历史时代约束下的设计；设计取舍直接体现在战斗中；战争由政府决定；国际紧张度；玩家会被撤职 |
| **Ultimate Admiral: Dreadnoughts** | 设计 + 3D 海战，模拟深度不如 RTW |
| **Kerbal Space Program** | 物理模拟本身就是玩法 |
| **From the Depths / Cosmoteer / Nebulous / Children of a Dead Earth / HighFleet** | "自己造自己打"的沙盒建造模式 |
| **Arms Trade Tycoon: Tanks** | 和"军火制造商"身份比较接近（具体机制待调研） |
| **Command: Modern Operations、Sea Power、HOI4** | 战争系统层级的参考（见第 10 节） |

### 2.2 战舰设计游戏的三种身份模式

| 模式 | 代表 | 特点 |
|---|---|---|
| 海军最高领导，设计和指挥一手包办 | RTW、UA:D | 循环最顺，但没有商业竞争 |
| 沙盒建造，自己造自己打 | From the Depths 等 | 几乎没有经营成分 |
| **军火商 / 制造商** | 很少见 | **本作所在的位置** |

### 2.3 市场定位
以"制造商"为主角、又有扎实物理设计的**军用飞机**游戏，目前基本空白。目标玩家：航空爱好者、硬核模拟和经营游戏玩家、RTW 和 DCS 玩家群体。

## 3. 玩家身份：严格扮演制造商

### 3.1 讨论过的方案

| | 严格制造商 ✅ 采用 | 超现实空军司令 |
|---|---|---|
| 独特性 | 高 | 低（和 RTW、HOI4 撞车） |
| 真实性 | 高 | 低：司令不能宣战，也不直接设计飞机 |
| 多国差异化 | 强 | 弱 |
| 战争参与感 | 中，用战时决策和观战补足 | 高 |
| 开发成本 | 低，可复用现有战争系统 | 高 |

另一个方案是"制造商 / 国有设计局 + 空军司令"双身份可选，但会让工作量翻倍，所以不进入主线。

### 3.2 结论
- **主线严格扮演制造商**：玩家不直接操作战争，只收到 AI 模拟的战争结果。结果影响厂商声誉，并大幅影响后续销路。
- 参与感通过**战时经营决策**（第 11 节）、**试飞员演习**（第 12 节）和**观战模式**来补足。
- 想指挥战争的玩家，可以玩独立的**沙盒模式**（第 13 节）。

### 3.3 制造商的权限边界（符合现实）
- **不能宣战**：战争是政府决定的外部事件。
- **不能自主决定卖给谁**：出口必须经过政府审批。
- **可以决定**：造什么、押注什么技术、推销哪个市场、给什么条件、要不要游说。

## 4. 可选国家与制造商类型

不同国家的"制造商"身份差异很大，正好变成不同的玩法：

| 类型 | 代表国家 | 玩法特点 |
|---|---|---|
| **私营公司** | 美国、法国、英国、瑞典 | 竞标、外销、现金流、破产风险 |
| **国有设计局** | 苏联、中国 | 与其他设计局争夺国家任务（如米格、苏霍伊、雅克之间的竞争）；靠政治关系和预算；**没有出口权**，出口由国家机构统一决定 |
| **跨国财团** | 欧洲联合项目（如狂风、台风） | 多国分工，政治妥协，各国需求互相冲突 |
| **许可生产 / 追赶型** | 日本、印度、以色列 | 仿制 → 许可生产 → 自主研发 |

- 主打外销玩法时，**法国**最合适：政府积极支持出口，达索是私营公司，史实外销案例丰富。
- 苏联也有"军事工业委员会"（ВПК），所以军工复合体这个主题在美苏两边都成立。

## 5. 核心循环

```mermaid
flowchart LR
    A[科技研发] --> B[设计翼型与机体]
    B --> C[内置模拟器估算]
    C --> D[风洞实验]
    D --> E[原型机试飞]
    E --> F[竞标 / 外销]
    F --> G[生产与交付]
    G --> H["实战（AI 模拟）"]
    H --> I[声誉与战报]
    I --> J[新需求 / 新招标]
    J --> A
```

### 5.1 不确定性是核心机制

| 阶段 | 成本 | 作用 |
|---|---|---|
| **内置模拟器** | 低、快 | 给出带误差范围的估算，如最大速度 1.8 ± 0.15 马赫 |
| **风洞实验** | 中 | 缩小误差，发现隐藏问题，如大迎角下突然失速 |
| **原型试飞** | 高 | 暴露颤振、尾旋、发动机喘振等"惊喜" |
| **竞标** | — | 在数据仍不确定时承诺性能：赌对了赢，吹过头了被罚款 |

风洞不是摆设，而是一个**风险管理的决策**。

## 6. 飞机设计与物理模拟

### 6.1 不需要真 CFD
用真实概念设计阶段的半经验工程方法，实时性好，结果"可信、趋势正确"即可。

| 模块 | 方法 | 实时性 |
|---|---|---|
| 2D 翼型 | 面元法 + 边界层（类似 XFOIL） | 毫秒级 |
| 3D 机翼 / 全机气动 | 涡格法 VLM（类似 AVL） | 很快 |
| 阻力、超音速波阻 | DATCOM、Raymer 经验公式，面积律估算 | 很快 |
| 重量、航程、爬升、盘旋 | Raymer / Roskam 概念设计公式 | 很快 |
| 发动机 | 参数化循环分析（研发方式见 6.4） | 很快 |

**难点**：跨音速和超音速区间。

### 6.2 翼型绘制
- **参数化模式**（NACA 系列、CST 参数）：适合新手。
- **自由绘制模式**：给硬核玩家。

### 6.3 科技树（1945–2030）
科技树按时代约束可用技术，防止玩家用后见之明碾压历史。

| 时代 | 代表技术 |
|---|---|
| 1945–1955 | 涡喷、后掠翼、跨音速气动、机炮、早期雷达 |
| 1955–1970 | 加力燃烧室、面积律、三角翼、可变后掠翼、第一代空空导弹、马赫 2 |
| 1970–1990 | 低涵道涡扇、电传操纵、放宽静稳定、边条翼、脉冲多普勒雷达、全向近距导弹 |
| 1990–2015 | 隐身外形与材料、超音速巡航、推力矢量、有源相控阵雷达、数据链、主动雷达制导导弹 |
| 2015–2030 | 变循环发动机、无人僚机、传感器融合、高超音速武器、第六代战机概念 |

其他分支：材料（铝合金 → 钛合金 → 复合材料）、制造工艺、航电、武器集成。

### 6.4 发动机研发
发动机采用 **"科技树 + 具体发动机研发项目"** 两层结构：

**第一层：科技树决定能力上限**
- 解锁发动机类型：涡喷 → 加力涡喷 → 低涵道涡扇 → 变循环
- 提升核心参数的上限：涡轮前温度、总增压比、材料耐温、部件效率

**第二层：针对具体推力指标立项研发**
- 玩家立项一台具体的发动机，设定目标：**推力（干推 / 加力）**，以及可选的推重比、耗油率、尺寸
- 投入研发资源（资金、工程师、时间）
- 目标越接近当前科技上限，**成本越高、周期越长、风险越大**（推力不达标、可靠性差、延期）
- 研发完成后，发动机成为可用部件，参数由研发结果决定（带一定随机偏差）
- 可以对已有发动机做**改进型**项目，比如提高推力、改善可靠性，比全新研发便宜

**设计取舍**
- 新飞机配新发动机：性能好，但两个项目的风险叠加（史实中很多飞机项目被发动机拖累）
- 用成熟发动机：风险低，但性能受限
- 发动机研发周期通常比机体长，需要**提前规划**

## 7. 从物理数据到作战指标

在物理模拟和战争系统之间加一层**作战指标**：

| 作战指标 | 来源 |
|---|---|
| **超视距能力（BVR）** | 雷达距离、导弹性能、最大速度、实用升限 |
| **近距格斗能力（WVR）** | 持续 / 瞬时盘旋率、**单位剩余功率 Ps**、推重比 |
| **作战半径与载弹量** | 燃油系数、耗油率、挂架 |
| **生存力** | 雷达反射面积、速度、冗余设计、低空突防能力 |
| **出勤率** | 可靠性、每飞行小时所需维护工时 |
| **成本** | 单价、全寿命成本 |

**Boyd 能量机动理论（Ps 图）** 是连接气动模拟和空战结果的桥梁：对比两架飞机的 Ps 包线，就能看出在哪个高度和速度区间谁占优。

## 8. 竞标系统

- 军方按史实发布招标需求，比如 YF-16 对 YF-17 的轻型战斗机项目。
- 玩家和**本国史实存在的飞机项目**竞争（竞争厂商可以虚构化）。
- 评标综合考虑：**性能、价格、进度、技术风险、政治因素**。军方常常偏向老牌厂商。
- 对比试飞阶段由系统根据试飞数据自动评估（第一阶段玩家不亲自参与，见第 12 节）。
- 承诺的性能没有达到会被罚款、损失声誉，甚至导致项目取消。

## 9. 外销与地缘政治

### 9.1 流程
**玩家选择市场和方案 → 政府审批 → 与竞争对手竞标 → 交付与售后**

### 9.2 各国出口机制（现实参考）

| 国家 | 机制 |
|---|---|
| 美国 | 国务院发放出口许可；大额军售要通知国会；分政府对政府军售（FMS）和厂商直接销售（DCS） |
| 法国 | 跨部门委员会审批，政府积极支持出口 |
| 英国、瑞典 | 有出口许可制度，瑞典历来比较严格 |
| 苏联 | 设计局没有出口权，由国家机构统一出售 |

### 9.3 政府审批（玩家无法控制，但可以影响）
- 根据客户国和本国的外交关系决定批准概率
- 技术等级越高越难批 → 出口降级版是一种策略
- 可能突然禁运（客户与盟国开战、政府更替）
- 玩家可以游说，但要消耗政治资本

### 9.4 制造商的手段（史实参考）
- 航展、演示飞行、游说
- **专门为出口设计**（如诺斯罗普 F-5）
- **出口降级版**（如苏联的简化版米格出口型）
- 融资、补偿贸易、技术转让、本地组装
- 灰色手段：贿赂（1970 年代洛克希德贿赂案），被曝光后要承担后果

### 9.5 不同市场需求不同
- 第三世界国家：便宜、耐用、能在简易跑道起降、适应炎热气候
- 富裕盟国：高性能、技术转让、本地组装
- 由此产生设计取舍：**要不要做一款专门的外销机**

### 9.6 售后就是影响力
- 零件、维修、弹药都依赖制造商；停止供应可以让客户的空军瘫痪，这也是政府手里的筹码。
- 实战表现影响国际声誉，例如 1967 年战争后幻影 III 订单大增。

### 9.7 风险
- 卖出的飞机被用来打盟友 → 许可被吊销、舆论压力
- 技术泄露：被缴获或被仿制（1967 年禁运后以色列仿制幻影，做出"幼狮"）
- 客户国家政变，合同作废

### 9.8 地缘政治影响
制造商**不能直接决定战争结果**，但可以**改变地区力量平衡**，从而间接影响战争走向。

## 10. 战争系统

### 10.1 战争的来源
- 战争是**政府决定的外部事件**（参考 RTW）。
- **史实剧本**：朝鲜战争、中东战争等在相应年份大概率爆发。
- **国际紧张度**：由随机事件推动，超过阈值就爆发战争。
- 一方厌战（战争疲劳、领土损失）时进入和谈。
- **和平时期的有限冲突**：边境空战、拦截事件（如 1958 年台海空战、1981 年锡德拉湾空战），规模小，可以检验新飞机。
- 制造商对战争的影响：游说军方、出口改变地区平衡、卷入代理人战争。

### 10.2 战争系统层级的选择

| | CMO 式 | Sea Power 式 | HOI4 式 |
|---|---|---|---|
| 层级 | 战役 / 战术，平台级 | 战术，3D 实时 | 大战略 |
| 性能体现 | 强 | 强，直观 | 弱，压缩成几个数字 |
| 开发成本 | 高：庞大的数据库 | **非常高**：要程序化生成 3D 模型 | 低 |

**结论**：采用 **"HOI4 的外壳 + 简化 CMO 的内核"**，**全部由 AI 操作**，可以复用作者另一款游戏的战争系统。

```
战略层（HOI4 式）  ：战区地图、制空权、任务分配、生产与补给
      ↓ 每次空战
交战结算（简化 CMO）：发现 → BVR → 格斗 → 脱离，后台概率模拟
      ↓
输出               ：战报、交换比、损失原因 → 声誉、销路、新招标需求
      ↓（可选）
2D 回放 / 观战      ：俯视图回放关键交战
```

### 10.3 空战模型

**部署层**：每个机场有容量、维护能力，可以被轰炸；AI 决定每个机场部署哪个型号、多少架、执行什么任务。

| 任务 | 起作用的性能 |
|---|---|
| 空优 / 巡逻（CAP） | BVR、格斗、留空时间 |
| 截击 | 爬升率、最大速度、雷达 |
| 护航 | 航程、BVR、格斗 |
| CAS（近距支援） | 载弹量、低空性能、生存力 |
| 遮断 / 轰炸 | 作战半径、载弹量、速度、突防能力 |
| 侦察（可选） | 速度、升限 |

**每回合（如每天）的结算**：
1. **航程检查**：距离越远，留空时间越短，有效架次越少
2. **出勤率**：可用架数 = 部署数 × 完好率（可靠性、维护工时、机场条件）
3. **BVR 阶段**：
   - 发现概率 = f(距离, 雷达性能, 目标 RCS)
   - 命中概率 = f(距离, 导弹代际, 目标的速度与机动)
   - 双方各进行几轮互射
4. **格斗阶段**：按格斗交换比结算，交换比由盘旋率、Ps、推重比的差值算出，再乘以飞行员素质
5. **对地任务**：突破空中拦截和**地面防空（高炮、地空导弹）**后，按载弹量 × 命中效率结算
6. **损耗**：战损 + 事故 + 进入维修

### 10.4 地面战（与玩家的飞机无关的部分）
**不模拟具体地面部队，使用抽象战线：**

- **战线区段模型**：每段只有两个数字，即双方的地面强度。用兰彻斯特方程或"强度比 → 推进概率"推动战线。
- 地面 AI 规则很简单：强度比高就进攻，低就防守。
- **空军影响地面的三条路径**：

| 空中任务 | 对地面的影响 |
|---|---|
| CAS | 直接削减敌方区段强度 |
| 遮断 / 轰炸 | 降低敌方补给，强度恢复变慢 |
| 空优 | 决定前两者能否执行，同时阻止敌方对你做同样的事 |

- 备选方案：**史实剧本 + 偏移**。地面战按史实时间线推进，空战表现好，战线就往有利方向偏。

### 10.5 战报
战报一定要**可读**，告诉玩家为什么输，例如：
> "F-4 在 BVR 阶段占优，但导弹可靠性太差，被拖进格斗后损失惨重。72% 的损失发生在近距格斗，原因是持续盘旋性能不足。"

---

## 11. 制造商在战争中的参与

玩家不指挥战争，但要在战争中**作为制造商做决策**：

| 战时决策 | 说明 |
|---|---|
| **紧急增产** | 扩大产能，承担债务和战后产能过剩的风险 |
| **战场改进 / 快速改型** | 根据战报出改型。史实例子：越战暴露 F-4 没有机炮，后来推出带机炮的 F-4E |
| **派驻技术代表** | 提高前线出勤率，收集一手数据，改善下一代设计 |
| **战时交付优先级** | 先满足本国还是出口客户，影响政府关系和国际声誉 |
| **观战模式** | 可视化战况，看到自己的飞机在打仗 |

## 12. 原型机试飞

### 12.1 第一阶段：只做试飞，不做空战演习，暂时不做画面
- 原型机造好后，由**厂商试飞员**执行试飞科目，验证性能并发现问题。
- 试飞在后台计算，结果以**数据和文字报告**呈现，例如：
  > "第 14 架次：M0.92 俯冲时出现副翼反效，速度限制暂定 M0.9。建议加强机翼扭转刚度。"
- **试飞科目**（玩家选择做哪些、做到什么程度）：

| 科目 | 验证内容 | 可能暴露的问题 |
|---|---|---|
| 低速 / 起降 | 失速速度、起降距离 | 失速特性差、翼尖失速 |
| 速度包线扩展 | 最大速度、俯冲极限 | 颤振、跨音速抖振、操纵反效 |
| 高度包线 | 实用升限、爬升率 | 发动机高空熄火 |
| 机动性 | 盘旋率、过载 | 结构强度不足 |
| 大迎角 / 尾旋 | 尾旋进入与改出 | 无法改出尾旋（可能坠机） |
| 武器 / 挂载 | 挂弹后的性能、投放安全 | 挂载引起颤振、分离不安全 |

- **取舍**：试飞科目越完整，误差越小、隐藏问题越少暴露在服役阶段，但成本和时间越高。跳过科目可以更快交付，但交付后出问题会损失声誉、被罚款。
- **试飞员**：有经验值和风险。危险科目可能导致坠机，损失原型机和试飞员。
- 试飞数据会反馈给内置模拟器，**缩小同类设计今后的估算误差**。

### 12.2 以后的扩展
- 玩家操控试飞员参加**对比试飞或空战演习**，表现影响销售。
- 加成有上限（约 ±10–15%），并提供 AI 代飞选项。
- 用 **JSBSim** 作为飞行动力学内核，加入简化画面。

- 独立于主线战役。
- 玩家可以用自己设计的飞机**亲自指挥**一场战争，比如分配机场部署和任务包。
- 满足想指挥的玩家，又不破坏主线的真实性。

## 14. 平衡要点

1. **防止玩家用后见之明碾压历史**
   - 科技树卡住材料、发动机、制造工艺
   - 新技术风险高：误差大、成本高
   - 评标综合考虑价格、进度、风险、政治
2. **空军对地面战的影响要明显，但要有上限**。参考值：完全掌握制空权时，地面推进效率提升 30–50%。
3. **数量也有自己的质量**：性能占优但昂贵、出勤率低的飞机，可能打不过便宜量大的对手。
4. **设计比操作更重要**：以后加入空战演习时，试飞员加成要有上限。
5. **战报要可读**：玩家必须知道该怎样改进设计。
6. **长时间跨度的节奏**：1945–2030 共 85 年，早期技术跳跃快、项目多，后期项目少、周期长、单价高。要防止后期变得冗长，比如加快时间推进，或者让一个项目同时衍生多个改型。

## 15. 外部飞行模拟器导出

### 15.1 DCS 的可行性
| 类型 | 形式 | 能否自己做 |
|---|---|---|
| SFM（简单飞行模型） | Lua 表格（马赫数 - 升阻系数、推力表等） | ✅ 社区 Mod 普遍在用；和本作的数据结构很契合 |
| EFM（外部飞行模型） | C++ DLL，官方 SDK | ⚠️ 一般只提供给签约的第三方 |

**难点**：程序化生成 EDM 格式的 3D 模型；没有座舱，只能给 AI 用或借用通用座舱；商业授权；DCS 更新导致 Mod 失效；多人服务器的完整性检查。

### 15.2 推荐路线
1. 游戏内**嵌入 JSBSim**（LGPL），先用于后台试飞计算，以后再用于试飞画面和空战演习
2. 提供 **FlightGear / X-Plane 导出**
3. 游戏有热度后，再和 Eagle Dynamics 洽谈 **DCS 官方合作**

- 定名前检查 Steam 同名、商标注册和域名

## 17. MVP 范围与开发路线

### 17.1 MVP
- **一个国家、一个时代切片**：美国 1945–1960 年（项目多、技术跳跃大、资料丰富）。完整游戏覆盖 1945–2030，MVP 只做第一段
- 2D 翼型 + 涡格法 + 经验公式
- 发动机科技树 + 发动机研发项目（该时代的涡喷 / 加力涡喷）
- 原型机试飞（无画面，数据和文字报告）
- 5–8 个史实招标项目
- 目标：验证"设计 → 测试 → 投标"循环是否好玩

### 17.2 后续阶段（建议顺序）
1. 战争系统接入（复用现有系统）+ 战报
2. 外销与政府审批
3. 时间线向后扩展：1960–1990 → 1990–2030
4. 更多国家与制造商类型（法国 → 苏联 → 欧洲财团 → 追赶型）
5. 沙盒模式
6. 试飞员空战演习、试飞画面（JSBSim）
7. 外部模拟器导出

### 17.3 可以先做的技术原型
- 画翼型 → 算升阻曲线的网页 demo
- 交战结算原型：输入两架飞机的参数，跑一千次模拟，输出交换比和战报
- 战争最小原型：两三个机场、两条战线区段、两种飞机，跑几十回合
- 气动数据 → JSBSim XML → 飞行仿真的数据链路验证
